# AI 作曲退化排查与独立试听

本轮只增加离线分析与试听文件。未修改正式提示词、校验器、配器、旋律或和弦；未调用 API、未实际输出 MIDI 声音。

## 结论先看

不能把问题简单归为“旧规则过时”。当前有三类差异需要区分：

1. **新作品对原有规则的遵守变差。** 对 FINAL 20 首累计 368 个强拍起音，有 39 个非当前和弦音，遵守率约 89.4%。新作 15:24 为 16/24，15:28 为 12/18，均约 66.7%。这是按音符累计的离线检查，不是历史人工评分，也不把非和弦音一律判错。
2. **历史试听入口与当前入口可能不同。** `blind_listen.py` 调用 `score_player.py`，仅旋律和持续和弦，无鼓、无贝斯、无动态配器。当前主演示使用完整配器。这是代码证据，但不证明用户当时远程试听必然使用这个入口。
3. **正式音乐规则未被最近改写，模型默认值和渲染方式变化了。** 对比 FINAL 提交 6f8dd73，client 的提示词、模板、开头轮换和 validator 相同；默认模型从 glm-4-flash 改为 glm-5.3-flash，并增加对应请求参数。实际可由环境覆盖，存档缺少完整请求元数据，不能断言新旧作品实际用了哪些模型。

“同一份提示词”不意味着“同一模型、同一输出质量”；目前不建议因为这两首失败就重新收紧整套音乐规则。

## 尊重此前裁决

`docs/api-line-tasks.md` 第十五、十六节记录：开头形态按种子轮换；强拍规则当时保留并观察；删除模糊轮廓条款；密度3～6、空洞≤8格保持；生成音域实验搁置。
本轮不改变这些决定。逐首自动空洞修复、强拍吸附、长音吸附、统一主和弦尾声均未实施。
仓库 blind_sheet.csv 为空，blind_key.json 只留下一个映射，不能据此判断具体曲目是否通过用户试听。
选取的两首 FINAL 曲仅为候选参考，不宣称是“用户确认成功曲”。待用户指明认可曲目后可替换，分析脚本可复用。

## 试听：先听三份就够

先以 `new_1528`（《疾速律动》）为例，在同一 MIDI 设备上依次听：

| 文件前缀 | 听什么 | 如何解释 |
|---|---|---|
| A_solo | 原旋律独奏 | 独奏也乱，先查作品本身 |
| B_simple | 原旋律＋旧简易持续和弦 | 若这里协调而完整版冲突，配器是重要因素 |
| F_dynamic | 原旋律＋当前动态配器 | 与前两者比较，定位新增伴奏影响 |

每个文件夹同时提供 MIDI（.mid）和播放事件（.json）。MIDI 是离线乐谱文件，不是已经渲染的录音。
所有 MIDI 使用与项目相同的 GM 音色编号：钢琴旋律、钢琴和弦、贝斯和鼓。不同播放器的音源仍可能不同；比较时使用同一播放器/音源。
提供 `_same_tempo.mid` 版本，把同一曲的所有版本统一为乐谱 BPM，排除速度差异。
若使用项目原有 MIDI 设备，推荐以下方式（在项目根目录、装有项目依赖的 Python 环境运行）：

```powershell
python reports/ai_listening_audit/listen.py new_1528 A_solo --device 1 --same-tempo
python reports/ai_listening_audit/listen.py new_1528 B_simple --device 1 --same-tempo
python reports/ai_listening_audit/listen.py new_1528 F_dynamic --device 1 --same-tempo
```

设备号换成平时使用的号。工具只播放已存事件，不联网、不重新作曲；Ctrl+C 停止。

## 完整对照设计

曲目：`old_C` = FINAL/pV3_p1_1，`old_Am` = FINAL/pV3_p1_2，`new_1524` 和 `new_1528` = 两首新曲。

| 前缀 | 版本 |
|---|---|
| A_solo | 只保留原谱旋律 |
| B_simple | FINAL 时的简易播放器 |
| C_frozen | FINAL 提交 6f8dd73 的配器 |
| D_pre_dynamic | 392c0a6，动态配器接入前 |
| E_current_static | 当前配器的静态路径 |
| F_dynamic | 当前动态配器 |
| G_actual_session | 仅新曲提供，当次归档的真实播放事件 |

共4首×6条对照路径，各有原速度和统一速度两份 MIDI，另2份真实会话 MIDI，共50份。
所有主对照统一使用 15:28 的动作时间线和整体强度 1.0，让曲目与配器可比较；**这不是重现旧曲当时的动作条件**。旧曲缺少已确认的原始动作对应，不能凭空补造。
15:24 的 G 是当时真实控制条件；其 F 使用共同控制，与 G 不应直接当作单因素对照。
前奏长度、音区、伴奏密度等版本差异按原代码保留；统一速度版本仅排除速度差异。
同曲 D/E 用于检查近期静态路径兼容，E/F 用于隔离动态配器；C/D 用于检查更早的前奏变化。
24条路径均验证输入乐谱未被修改，50份 MIDI 的头、轨道长度、事件编码和结束标记通过离线解析检查。
未实际试听，不能凭这些检查宣布哪版最好听。

## 具体问题位置（小节从1计数）

- 《高能律动十六拍》第2小节第0格：旋律 C，伴奏 G；同样形态重复到第6、10、14小节。第3小节第8格：旋律 G 持续4格，伴奏 Am。它们属于当前提示词已有约束的检查对象，不是新加规则。
- 《疾速律动》第1小节第0格：旋律 D，伴奏 C；第2小节第8格：旋律 D，伴奏 Am。
- 《疾速律动》第12小节第0、8格：C 音各持续4格，伴奏 G；尾声继续延长 G。这里“末音回主音”与“强拍和弦音/循环模板”可能相互冲突。直接把 C 吸附成 G 和弦音，会牺牲原有末音主音要求，不能不经审阅就改。
- 弱拍短非和弦音只是观察项，要结合进入和解决方式判断，不等同于错音。

更完整的位置见 `score_checks.json`；实际小节播放秒数可按各版本 BPM 和前奏换算，不能在不同版本共用同一秒数。

## 待审阅的最小修改方案（均未执行）

| 候选 | 用通俗话说 | 是否改变音乐自由度 | 风险/审阅重点 |
|---|---|---|---|
| 记录生成来源 | 保存实际模型、变奏、模板、附加规则、修复记录；绝不保存 key | 不改变 | 以后能重现问题；现在的存档无法补回缺失信息 |
| 现有规则只读检查 | 告诉你哪些地方未遵守已定规则，不自动改音 | 不改变 | 非和弦音不一律贴“难听”标签 |
| 配器单独减让 | 若 B 好而 F 差，先降低/缩短发生冲突的伴奏 | 不改旋律规则，会改听感 | 需要同曲试听，避免伴奏过空 |
| 强拍或长音自动修复 | 把某些音改为更贴合伴奏的音 | 会改变 | 可能破坏旋律方向与结尾；不是默认候选首选 |
| 结尾旋律与和弦统一 | 一起决定最后落在哪里 | 会改变模板或末音 | 原规则可能冲突，必须选择优先级 |

建议先听 A/B/F，再决定走“配器减让”还是“旋律修复”。没有证据支持直接把全部非和弦音吸附掉，也不建议此时增加新规则或追加付费批量生成。
