# 新旧音乐流程对照结果

对照版本：392c0a6（2026-09-11 02:12）与当前工作区。仅离线生成事件，未播放 MIDI，未刷写板子。
本轮没有修改产品代码或阈值，问题尚不能宣称解决。

## 方法

从 7 份归档 input.csv 重新运行原始画像计算，新旧结果逐份相等。
保留每次归档当时的个人校准状态，不使用后来才放入录制目录的 baseline。
规则作曲固定 seed=42；事件模式不加姿态或视觉音区，以单独比较音乐处理。
分别运行旧作曲+旧配器、新作曲+旧配器、当前静态配器、当前动态配器。
旧模块依赖的画像和节奏等公共模块与旧提交无差异；事件模块引用的分档和速度函数也无差异。
产出 13 组有效比较（桌面静止数据无足够事件，只有规则模式），每组 4 份播放事件 JSON。
音色由未改变的 MidiEngine 决定；本实验未实际调用合成器，不将统计结果等同于听感结论。

`old/` 保存加载的旧源码；`before_audit/` 保存本轮检查开始时的当前核心代码。
`comparison.json` 为完整比较；`raw_checks.json` 为原始读数检查。
运行 `python reports/compare_music_versions.py` 可复现（需项目 Python 依赖）。

- 13:06 数据：新旧均判激烈、整体强度 100%。规则版旧速度 199.8，新版 185 BPM。新旧都高。
- 14:02 数据：新旧均判激烈、强度约 73.7%。规则版旧速度 99.716，新版 90 BPM。
- 14:07 数据：新旧均判中等、强度约 60.7%。事件版旧速度 144.504，新版 136 BPM；旧旋律 46 个音，新版 29 个。仅回退配器不能据此保证恢复舒缓。
- 14:09 桌面静置：新版无播放事件，不能当作舒缓挥动成功样本。

## 原始数据异常：优先验证采集量程

用户确认 14:09 指挥棒全程放桌上。1499 条样本的转动合量均低于活动阈值，
加速度合量中位数却为 41.832 m/s²，约 4.27 g。正常静置应接近 1 g。
凌晨 02:37 低转动样本的加速度合量中位数为 9.680；13:08 的对应值为 41.234。
低转动不一定代表静止，因此后两者只是辅助证据，桌面静置是直接证据。
13:08 三轴读数共 4500 个，其中 255 个绝对值至少 17.4，接近仓库固件配置下的换算边界。

仓库固件按加速度 ±8g / 4096 LSB/g、陀螺仪 ±1000 deg/s / 32.8 LSB/(deg/s) 换算。
初始化虽然写量程寄存器，但 writeRegister 不检查写入结果，也未读回验证量程；身份异常仍继续运行。
因此“初始化未生效/传感器配置与换算不符”是需要验证的假设，不能当成已证实原因。
还需排查实际烧录固件不同、传感器状态或读数异常。仓库源码未变不证明板上运行状态未变。
加速度异常不能直接证明陀螺仪也恰好放大四倍；禁止直接对 CSV 除以四或自动重新校准掩盖问题。
