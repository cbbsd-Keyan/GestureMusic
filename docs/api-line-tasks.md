## 一、这条线在做什么（30 秒版）

```
挥动 10~30 秒
  → 动作画像 JSON（节奏/能量/姿态，手势线已完成）
  → 大模型写乐谱 JSON（音符编号列表）        ← AI 只做这一步
  → 校验修复（越界音符自动钳位）
  → GM 音源播放（Windows 自带合成器）        ← 声音从这里来，与 AI 无关
```

**核心认知：AI 出脑子，音源出声音。**
大模型生成的是"音符编号"（如 60 = 中央 C），播放走 MIDI 音源的
预录乐器采样——**物理上不可能出现人声**。
之前"国内 API 生成纯音乐带诡异人声"是走错了赛道（那是音频生成模型，
本方案从头到尾没用它）。国外 API 方向作废。

## 二、目标与验收指标

| 指标 | 要求 |
|---|---|
| 端到端延迟 | 画像进入 → 出声 ≤ 15 秒 |
| 生成质量 | 20 首盲听合格率 ≥ 60%（乐理负责人打分） |
| 演示鲁棒性 | 断网/超时/坏 JSON 三种故障下 100% 有声音（回退链） |
| Go/No-Go | 合格率 <50% 则整体转纯规则作曲（管道复用，不浪费） |

## 六、已知坑（都替你踩过了）

1. **Windows 重定向编码**：`> file.json` 默认 GBK——项目里的脚本已强制
   UTF-8，队友自己写新脚本时记得加
   `sys.stdout.reconfigure(encoding="utf-8")`
2. **模型返回 markdown 包裹的 JSON**：`client.extract_json` 已做剥离+正则兜底
3. **不要**试图让模型"生成音乐/音频/WAV"——整条歧路，见第一节
4. 充值 20 元够全部开发+演示（单次几分钱）
